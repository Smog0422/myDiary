# Spec: MyDiary V2（二期改进）

## Problem Statement

MVP 已可运行，但存在以下问题：
1. 任务触发机制过于简陋——只有固定 weekly/monthly，无法指定"周几"/"几号"触发
2. 缺少追溯控制——用户可能不希望补生成历史周期
3. 缺少停止/隐藏机制——无法暂停或隐藏模板而不删除
4. 多处 UI bug：换色不生效、文字未居中、无操作反馈
5. 统计页无法查看单条打卡明细
6. 整体视觉风格简陋，需要"自然、简洁、大气、淡色系"的设计语言

## Solution

### 1. 任务触发机制重构

**TaskTemplate 新增字段：**

| 字段 | 类型 | 说明 |
|---|---|---|
| `triggerDay` | Int | 周任务：1-7（周一=1）；月任务：1-28（几号） |
| `backfill` | Boolean | 是否追溯补生成（默认 false） |
| `active` | Boolean | 是否活跃（停止 = false） |
| `hidden` | Boolean | 是否隐藏（隐含停止） |

**触发规则：**
- App 启动时 + WorkManager 每日检查：
  - 如果 `!active || hidden` → 跳过
  - 计算当前周期 key
  - 如果该模板+周期已有实例 → 跳过（幂等）
  - 如果 `backfill == false` 且今天 < 本周期触发日 → 跳过（等下个触发日）
  - 否则 → 生成实例

**停止/隐藏状态机：**

```
活跃 ──停止──→ 停止 ──隐藏──→ 隐藏
 ↑               │               │
 └───────────────┴───────────────┘
          恢复（隐藏→停止，停止→活跃）
```

- 隐藏必然停止；恢复隐藏 → 回到停止态，不自动激活
- 隐藏的任务：首页/管理页任务列表不可见，统计页仍可见，通过"任务管理"入口可查看/操作

### 2. UI Bug 修复

| # | 问题 | 修复 |
|---|---|---|
| 3 | 换色后首页颜色未更新 | 排查 Flow 收集链路，确保 `observeAll()` 在 recolor 后触发重组 |
| 4 | 首页标签圆圈：颜色未应用 + 文字未居中 | 修复 CheckInButton 的 background color 和 text alignment |
| 5 | 换色无成功反馈 | 对话框关闭后，标签行颜色圆点立即变化（Flow 驱动）；可选：短暂 toast |

### 3. 统计页明细弹窗

点击某个标签的聚合数字 → 弹出底部抽屉/对话框，展示该标签在**当前选中时间范围**内的所有打卡记录：
- 每条显示：时间（格式化）+ 备注（无则显示"—"）
- 可滚动
- 按时间降序

### 4. 视觉风格重设计

方向：**自然、简洁、大气、淡色系点缀**
- 通过 HTML prototype 提供 3 种方案供用户选择
- 选定后更新 Compose Theme（Color.kt, Type.kt, Theme.kt）
- 全局应用：背景、卡片、按钮、文字颜色

## User Stories

1. As a 用户, I want 设置周任务在"周三"触发, so that 我的游戏每周三刷新，App 自动对齐
2. As a 用户, I want 设置月任务在"5号"触发, so that 月度活动在 5 号开始
3. As a 用户, I want 关闭追溯, so that 我周二设置"周一触发"，本周不会突然冒出一份任务
4. As a 用户, I want 停止一个模板, so that 最近几周不想被打扰，但保留配置
5. As a 用户, I want 隐藏一个模板, so that 任务列表清爽，但统计里还能看到历史
6. As a 用户, I want 恢复隐藏的任务, so that 我需要时能找回它（恢复后为停止态）
7. As a 用户, I want 换色后立即在首页看到新颜色, so that 我知道操作成功了
8. As a 用户, I want 首页标签文字居中, so that 视觉整洁
9. As a 用户, I want 点击统计数字后查看明细, so that 我能回忆"那次是什么时候、写了什么"
10. As a 用户, I want App 整体风格自然大气, so that 每次打开心情舒适

## Implementation Decisions

### 数据模型（Migration v3 → v4）

```sql
ALTER TABLE task_templates ADD COLUMN `triggerDay` INTEGER NOT NULL DEFAULT 1;
ALTER TABLE task_templates ADD COLUMN `backfill` INTEGER NOT NULL DEFAULT 0;
ALTER TABLE task_templates ADD COLUMN `active` INTEGER NOT NULL DEFAULT 1;
ALTER TABLE task_templates ADD COLUMN `hidden` INTEGER NOT NULL DEFAULT 0;
```

### 触发判断（PeriodSyncService 重写）

```kotlin
fun shouldGenerate(template: TaskTemplate, today: LocalDate): Boolean {
    if (!template.active || template.hidden) return false
    val periodKey = currentPeriodKey(template, today)
    if (instanceExists(template.id, periodKey)) return false
    if (!template.backfill && today < triggerDate(template, today)) return false
    return true
}
```

### WorkManager

- 每日 0:01 执行 `PeriodSyncWorker`
- App 启动时 `MainActivity.onCreate` 兜底调用同一逻辑
- 双保险，幂等

### UI 架构不变

- 仍为 4 Tab（首页/统计/管理/设置）
- 管理页增加"已隐藏任务"折叠区域
- 统计页标签行可点击 → 底部 Sheet

## MVP 边界（本期）

- ✅ 触发日配置 + 追溯开关 + 停止/隐藏
- ✅ UI bug 修复
- ✅ 统计明细弹窗
- ✅ 视觉风格重设计
- ❌ WorkManager 精确闹钟（用每日检查即可）
- ❌ 模板删除功能（用户明确不要）
- ❌ 任务项拖拽排序

## Testing Decisions

- PeriodSyncService 触发逻辑：纯函数单元测试（给定 today + template 状态 → 是否生成）
- UI bug：手动验收
- 视觉风格：HTML prototype → 用户选定 → 应用

## Out of Scope

- 模板删除
- 多组模板（同一周期多个周模板）
- 任务项编辑/排序
- 通知权限流程（睡前提醒仍为三期）
