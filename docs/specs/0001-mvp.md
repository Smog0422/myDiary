# Spec: MyDiary MVP（一期）

## Problem Statement

我是一个有周期性游戏任务（每周/每月）的玩家，同时希望追踪自己的日常行为（排便次数、克服诱惑的次数）。目前这些信息散落在记忆和聊天记录里：睡前无法快速确认"这周有没有漏掉什么任务"，也无法回答"上个月我克服了幾次诱惑、都是什么类型"。我需要一个安卓 App，让我在 3 秒内记下一笔行为，在睡前 30 秒内看清本周期任务的完成情况，并能按周/月/年复盘历史数据。

## Solution

一个离线优先的安卓原生 App（Kotlin + Jetpack Compose + Room），包含四个页面：

1. **首页**：本周期任务清单（可逐项勾选）+ 快捷打卡区（最近常用标签的大按钮，点击即记录，可选备注）
2. **统计页**：按周/月/年 × 按标签聚合的打卡数字列表 + 游戏任务历史完成率
3. **管理页**：标签管理（增删改、名称、颜色）+ 周/月任务模板编辑
4. **设置页**：JSON/SQL 导出、JSON 导入、睡前提醒开关

数据全部存本地 Room 数据库，无服务器。备份手段为手动导出/导入文件。周/月任务由模板按自然周期（周一 0 点 / 1 号 0 点）自动生成实例，过期实例保留为历史（未完成项标记"未完成"），不删除。

## User Stories

1. As a 用户, I want 创建自定义标签并设置名称和颜色, so that 我可以用自己的分类体系记录一切行为
2. As a 用户, I want 编辑已有标签的名称和颜色, so that 我的分类可以随习惯演变
3. As a 用户, I want 删除一个标签, so that 我可以清理不再使用的分类；删除后历史打卡事件保留并标记为"已删除标签"，不丢数据
4. As a 用户, I want 在首页看到最近常用标签的快捷按钮, so that 我上完厕所后打开 App 点一下就能完成记录
5. As a 用户, I want 点击标签后可选填一句备注, so that 我可以补充上下文（如"今天没忍住买了皮肤"）但不被强制
6. As a 用户, I want 打卡动作在 3 秒内完成, so that 记录的低摩擦让我能长期坚持
7. As a 用户, I want 在首页看到本周期（本周/本月）的任务清单, so that 我睡前能逐项确认完成情况
8. As a 用户, I want 逐项勾选任务完成状态, so that 我能直观看到"5 项里完成了 4 项"
9. As a 用户, I want 编辑周任务模板（增删任务项）, so that 每周的固定事项不用重复录入
10. As a 用户, I want 编辑月任务模板, so that 每月的大目标也有清单可对照
11. As a 用户, I want App 在周一 0 点 / 1 号 0 点自动生成新的任务实例, so that 我打开 App 时新一期的清单已经就绪，不需要手动触发
12. As a 用户, I want 即使几天没打开 App，回来时错过的周期实例也被补生成, so that 历史是完整的
13. As a 用户, I want 过期的任务实例保留为历史并标记未完成项, so that 我能复盘"上周漏了什么"
14. As a 用户, I want 在统计页按周/月/年查看打卡数据, so that 我能回答"上周、上个月、去年我克服了几次"
15. As a 用户, I want 统计数据按标签聚合展示, so that 我能看到"冲动消费 2 次、熬夜 1 次"这样的分类明细
16. As a 用户, I want 在统计页看到历史任务实例的完成率, so that 我能复盘每个周期的任务完成质量
17. As a 用户, I want 将全部数据导出为 JSON 文件, so that 我可以备份或迁移到别的工具
18. As a 用户, I want 将全部数据导出为 SQL 文件（可选格式）, so that 我将来上服务器时可以直接导入 MySQL
19. As a 用户, I want 从导出的 JSON 文件导入数据, so that 换手机时可以完整恢复
20. As a 用户, I want 导入时校验文件格式并给出明确错误提示, so that 我不会用坏文件覆盖现有数据
21. As a 用户, I want 一条可配置的睡前提醒（默认关闭）, so that 我可以可选地收到"看看今天任务完成了没"的提示
22. As a 用户, I want App 完全离线运行, so that 我的私密数据（排便、克服诱惑记录）永远只存在于我的设备
23. As a 用户, I want 首页同时展示本周和本月两个任务清单, so that 我睡前一次看完所有周期的待办

## Implementation Decisions

### 架构与载体（见 ADR 0001）

- 安卓原生：Kotlin + Jetpack Compose + Material 3
- Minimum SDK = API 31（Android 12，覆盖主力机安卓 16 + 备用机安卓 12）
- 本地存储：Room（SQLite），无网络请求、无服务器
- 不加密数据库（应用私有目录已隔离）；关闭 Android Auto Backup，手动导出/导入为唯一备份手段

### 领域模型（见 ADR 0002、ADR 0003）

三条独立数据线：

1. **标签 Tag**：`{id, 名称, 颜色}`，用户自定义，是打卡的唯一分类维度。不存在"类型"字段——类型即标签
2. **打卡事件 Check-in**：`{id, 时间戳, 标签 id, 备注?}`；标签被删除后事件保留，展示为"已删除标签"
3. **任务线**：
   - **任务模板 Task Template**：`{id, 周期类型(周|月), 任务项[名称]}`
   - **任务实例 Task Instance**：`{id, 模板 id, 周期标识(如 2026-W29 / 2026-07), 任务项[名称, 完成状态]}`

任务清单独立于打卡事件，不并入标签体系（清单语义 vs 事件流语义）。

### 周期生成机制

- 边界：自然周（周一 0 点）、自然月（1 号 0 点）
- 触发：WorkManager 周期任务 + App 启动时兜底检查（双保险）
- 幂等：以"模板 id + 周期标识"为唯一键，已存在则不重复生成
- 补生成：启动时检查从"最近已有实例的下一期"到"当前期"之间的缺口，逐期补齐
- 过期实例不删除，未完成项保留原状态

### 页面结构（4 页面）

- 底部 Tab：首页 / 统计 / 管理；设置入口在管理页右上角
- 首页：上区任务清单（本周 + 本月两个区块），下区快捷打卡按钮（最近常用标签，4–6 个）+ "全部标签"入口
- 统计页：周/月/年三个粒度切换；打卡按标签聚合的数字列表；任务历史完成率单独区块
- 管理页：标签 CRUD + 颜色选择器；周/月模板编辑
- 设置页：导出（JSON 主 / SQL 可选）、导入、睡前提醒开关

### 导出/导入

- 手动触发，Android ShareSheet 分享文件
- JSON 为主格式（人类可读、跨工具通用）；SQL 为可选格式（为将来 MySQL 留路）
- 一期做全量导出；按时间/类型筛选为二期
- 导入仅接受 JSON；导入前校验（缺字段、类型错、重复 id），失败不覆盖现有数据

### MVP 边界

- **一期（本 spec）**：标签管理 + 打卡记录 + 手动任务清单 + 周/月模板自动生成 + 统计页 + JSON 导出/导入
- **二期**：SQL 导出、导出筛选、UI 打磨
- **三期**：睡前提醒

> 注：原共识中"一期不含自动生成"的切分在此调整——周期生成器是任务线的核心价值，且其逻辑纯函数化后测试成本低，故并入一期。睡前提醒移至三期（依赖通知权限流程，独立性强）。

## Testing Decisions

### 原则

只测外部行为，不测实现细节。一个好的测试描述"给定某输入，系统对外呈现什么结果"，不关心内部如何组织代码。

### 唯一自动化接缝：领域逻辑层

纯 Kotlin 模块，不依赖 Android 框架，包含：

| 模块 | 测试范围（外部行为） |
|---|---|
| 周期生成器 | 给定当前时间 + 已有实例集合 → 应生成哪些新实例？边界：周一 0 点前后、1 号 0 点前后、跨月、缺口补生成、幂等（不重复生成） |
| 统计聚合器 | 给定打卡事件集 + 时间范围 → 按标签聚合数字。边界：周/月/年切分、空数据、已删除标签的事件归属 |
| 导入校验器 | 给定 JSON 文本 → 合法/非法 + 具体错误位置。边界：缺字段、类型错、重复 id、空文件 |

### Room DAO 测试

使用 in-memory Room（`Room.inMemoryDatabaseBuilder`）跑真实 SQL：增删改查、删除标签后事件保留标记、实例唯一键约束。这是标准模式，不算新接缝。

### 不测的部分

- Compose UI 渲染与交互：单用户工具，靠手动验收
- 导出文件字节流：手动验收一次
- WorkManager 调度时机：真机观察

### Prior art

代码库当前为空项目（Studio 模板），无既有测试先例。`app/src/test` 下的 `ExampleUnitTest` 为模板占位，将被替换。

## Out of Scope

- 自由文字日记功能（共识 Q3 已砍）
- 服务器/云同步（ADR 0001：以后再考虑）
- 数据库加密、Android Auto Backup（ADR 0001）
- 游戏任务自动同步（无官方 API，共识 Q4：手动维护 + 模板生成）
- 排便目标制（共识 Q6：纯计数）
- 图表可视化统计（二期再议，一期为数字列表）
- 导出按时间/类型筛选（二期）
- 除睡前提醒外的任何推送通知（共识 Q12）
- iOS / 其他平台

## Further Notes

- 领域词汇以 `GLOSSARY.md` 为准；架构决策见 `docs/adr/0001–0003`
- 数据私密性高（排便、克服诱惑记录），任何未来引入网络功能的提案都需要重新过 ADR
- 用户为前端出身（Vue 3 + TS），Kotlin 代码应保持自解释风格，避免惯用法的炫技
- 分发方式：个人侧载 APK，不上架应用商店
