# ADR 0002: 标签即类型——用单一"标签"维度统一所有行为分类

## Status

Accepted（2026-07-18）

## Context

行为记录最初设计为两层结构：**固定类型**（排便 / 克服诱惑 / …）+ **可选标签**（冲动消费 / 熬夜 / …），即"类型是标签的父级"。用户指出"类型就是标签，同一个东西"，要求压平为一层。

候选方案：

1. **两层模型（类型 + 标签）**：语义分层清晰，但"排便"和"克服诱惑"变成系统内置概念，新增行为类别需要改代码；统计页需要两级下钻。
2. **单层模型（只有标签）**：所有分类都是用户自定义标签，每个标签带颜色；打卡事件 = 标签 + 可选备注 + 时间戳；新增类别零开发成本。

## Decision

采用**单层模型**：不存在"类型"字段，一切分类都是用户管理的标签。打卡事件结构为 `{时间戳, 标签, 备注?}`。

理由：

- 使用场景全部是用户自定义的（排便、克服诱惑只是当前例子），没有需要系统内置的分类；
- 单层模型让"加一个新习惯"（喝水、运动）退化为"建一个新标签"，产品可扩展性来自数据而非代码；
- 统计页按标签聚合即可满足"上周克服了什么、几次"的复盘需求，两级下钻是过度设计。

## Consequences

- 标签成为核心实体：其管理（增删改、颜色）必须在一期就做好，且删除标签时历史打卡事件的去留策略需要明确（建议：保留事件、标记为"已删除标签"，不丢数据）；
- 快捷区按钮完全由标签驱动，没有"固定入口"概念；
- 游戏任务清单**不**并入标签体系（见 ADR 0003），它仍是独立实体。
