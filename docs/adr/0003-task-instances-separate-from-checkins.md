# ADR 0003: 游戏任务清单独立于打卡事件，不并入标签体系

## Status

Accepted（2026-07-18）

## Context

在"标签即类型"的统一模型下，曾考虑把游戏周/月任务也做成标签（如"本周副本：目标 3 次"，每次打勾 = 一次打卡）。但任务清单与打卡事件语义不同：

- **任务实例**是清单语义：属于某个周期，有明确的项数，关心"5 项里完成 4 项、漏了哪一项"；
- **打卡事件**是事件流语义：只累计次数，没有"本期列表"概念。

用户的核心场景是"睡前看看这周有没有漏掉什么任务"——这要求任务保留为带周期归属的清单实体。

## Decision

数据模型保持两个独立实体：

1. **任务模板（Task Template）**：周模板 / 月模板，用户编辑；
2. **任务实例（Task Instance）**：由模板按自然周期（周一 0 点 / 1 号 0 点）自动生成的待办清单，逐项勾选；过期后保留为历史，未完成项标记"未完成"，不删除。

打卡事件（Check-in）与标签（Tag）构成另一条独立线。两者在统计页合并展示，但数据模型分离。

理由：

- 清单语义（完成率、漏项可见）无法用纯计数表达；
- 周期生成机制（模板 → 实例）只作用于任务，打卡事件没有"本期"概念；
- 分离后两条线各自可独立演进，统计层的聚合是展示层职责。

## Consequences

- 首页需要两个区域：任务清单区 + 快捷打卡区，信息架构按此设计（4 页面结构见设计共识）；
- 自动生成依赖 WorkManager 后台触发 + 打开 App 时兜底检查双保险；
- 历史数据量会随周期累积增长（每周/每月新增一份实例），Room 单表存储无压力，导出文件体积需留意。
