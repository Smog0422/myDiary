# ADR 0001: 选择安卓原生 App（Kotlin + Compose）+ 本地存储，放弃微信小程序

## Status

Accepted（2026-07-18）

## Context

需要一个"个人日记/备忘录"类工具，核心场景：睡前查看游戏周/月任务完成情况、随手记录行为（排便次数、克服诱惑）、按周/月/年复盘。载体在微信小程序与安卓 App 之间二选一。

候选方案：

1. **微信小程序**：开发快、免安装、秒开；但无法主动推送，数据需上云（微信云开发有配额与隐私问题），且上传发布时平台会校验网络请求域名，对纯本地工具是额外摩擦。
2. **安卓 App（Kotlin + Jetpack Compose + Room）**：原生体验、本地存储、可接系统通知与 WorkManager；代价是需要自行打包分发，Kotlin 对前端出身开发者有学习曲线。
3. **Flutter / uni-app x**：跨平台框架，语言仍需新学，且单机单平台场景下跨平台能力是纯开销。

## Decision

选择 **安卓 App，Kotlin + Jetpack Compose + Room**，数据存本地，不做服务器；提供 JSON（主）/ SQL（可选）导出与导入作为唯一备份手段。

理由：

- 使用模式是"低频打开、秒开秒走"，App 桌面快捷方式足以覆盖，免安装不是刚需；
- 数据高度私密（排便、克服诱惑记录），本地存储是唯一让数据完全留在用户手里的方案；
- 单用户、单平台、离线优先，原生栈的 Room / WorkManager / 系统通知均为第一方支持，无桥接层损耗；
- 用户明确希望导出 JSON/SQL 以便日后迁移或上服务器，本地数据库天然支持。

## Consequences

- 需要自行管理 APK 构建与更新分发（个人使用，直接侧载即可）；
- 无系统级自动备份（中国大陆 Google 服务不可用），数据持久性完全依赖用户执行导出习惯——这是已知且接受的风险；
- Kotlin/Compose 学习成本由开发者承担，换取后续维护的最低复杂度。
